# DataForSEO 建站与每周关键词规划

核心流程：**用户输入产品或关键词 → 理解产品与采购场景 → 调用已连接的SEO数据MCP → 分析与页面分配 → 交付可执行报告**。后续复用同一台账，根据实际产品、内容和反馈生成每周更新报告。

AI主动完成研究、筛选、聚类与报告；用户提供只有本人知道的产品能力、市场与网站情况，决定范围和关键取舍。创建或修改skill时只处理文件，不实际发起付费数据查询。

## 一、模式与必要输入

- **首次建站模式**：没有已确认规划或用户要新建网站时，生成网站制作报告、页面关键词映射与初始内容计划。
- **每周运营模式**：用户要本周选题、关键词更新或持续发布计划时，读取上次报告、关键词台账、已发布URL、实际新增产品与反馈，生成本周报告。
- **局部更新模式**：只新增某个产品或调整某个页面时，更新受影响的关键词与归属，不重做整站。

最小入口是一个产品名或种子词。优先读取当前会话及用户授权提供的Day1–Day3报告，复用目标国家、语言、企业客户、产品规格、站点和已有选择。缺少会改变查询结果的市场／语言或产品含义时，每轮只问1–3项；不要无说明默认美国或英语。用户不懂市场选择时先解释、研究并给建议，再确定数据查询范围。

首次没有网站不影响规划，URL用明确标注的拟定路径。每周没有历史记录时说明无法完成去重和变化比较，先建立基线，不能编造上周成果或已发布页面。新会话不声称自动记忆。

## 二、识别与调用实际MCP

读取 [DataForSEO接入与数据规则](references/dataforseo-workflow.md)，确认当前可用工具及参数。官方API文档不是MCP连接；API密码也不等于已在当前Agent暴露工具。

官方新版MCP可能通过 `docs_index`、`docs_list_sections`、`docs_search` 和 `api_request` 工作，其他封装可能提供专用关键词工具。以当前实际工具清单与schema为准，不假装存在 `research_keywords` 等名称，也不把HTTP端点当工具名直接调用。

需要查询时在用户已授权的数据用途、范围与预算内调用。不自动充值、升级、切换付费产品或无限扩大关键词深度；不默认展示接口价格、积分或编造费用。凭据只用使用者自己的连接或私密配置，不写入skill、报告、示例、截图和压缩包。不能借用原作者凭据；不能要求在聊天重新粘贴密钥。

MCP缺失、认证失败、权限或余额不足时，完成能独立推进的分析和报告结构，标记没有数据支持的部分，给接入／修复步骤或支持用户导入历史导出表。不得把草案冒充已调用MCP的报告，也不擅自改用直接API或付费工具。

## 三、先理解产品，再扩词

整理产品名称及本地叫法、用途、材质与规格、目标企业买家、采购问题、定制和供应服务。业务能力未知则标待确认，不能因为某个词有量，就称用户是工厂、制造商、现货供应或提供其没有的服务。

由这些维度提出种子词，再用MCP扩展相关词和长尾词。优先少量高相关种子，限定市场与返回范围，合并去重后批量补数据，避免同一组合重复查询。初始返回数量可设小规模，只有发现明确缺口时再扩展，不追求越多越好。

关键词同时包括产品采购、应用场景、材料与选型、定制、比较、维护和常见问题。排除不匹配的产品、求职、无关下载、错误地区和明显不相关意图；零售词是否保留由用户业务与实际结果决定，不机械删除所有信息词。

## 四、数据与意图分析

按当前接口能力取得近似月搜索量、月度历史、搜索意图、SEO难度与必要SERP信息；已返回所需数据则复用，不为凑全字段额外请求。

- 搜索量、月份、国家、语言、数据来源、更新时间和查询时间一并保存。结果为 `null`、未返回、无覆盖和真实0分别记录，未知不补0。
- 标准搜索量、clickstream或normalized指标保留各自标签，不能混成同一口径；近似月搜索量不是网站访问或询盘，不能简单相加同义词得到可获得流量。
- 广告竞争度、CPC与SEO难度分开；`keyword_difficulty`是供应商估算指标，不是本网站排名概率。没有该字段不从广告竞争度推算。
- API返回意图作为证据之一，结合关键词含义及必要的目标地区搜索结果判断；未实际检查SERP时标注，不编当前排名、竞品数据或“全网第一”。
- 综合产品匹配、采购价值、意图、内容可交付性、已有页面和可用数据排序，解释推荐理由。不能只按量排序，也不造精确权重或保证排名；相关的低量或无量词可保留并说明依据。

## 五、把词分到页面，而不是机械“埋词”

围绕用户的一类搜索需求建立词簇，同义或近似意图先考虑由一页承接；真正不同的产品、用途或意图才考虑新页面。每个重点词簇指定主要承接页，但正常相关词可在多页自然出现，不声称所有重复词都是冲突。

按实际内容设计首页、产品分类／集合、具体产品、应用或服务、选型比较、文章与FAQ。单一产品、材料不足时保持简单，不为每个颜色、关键词变体或城市制造低价值页面。关于、联系等页面服务信任和转化，不强塞商业词，也不把没有证据的资质写进标题。

每个首发页面必须写清：拟定URL、目标买家与需求、主词簇、辅助词、选择依据、推荐Title、H1、H2与内容模块、描述草稿、图片说明、内链与询盘动作。内容要能直接指导页面设计，不能只交一个大词表。

用词自然放在与内容相符的页面标题、主要标题、说明正文和相关内链；URL清晰且稳定。图片alt按实际图片描述，不给装饰图塞词。不设固定关键词密度，不做隐藏文本、不刷页脚词表、不把关键词meta标签当Google优化手段，也不保证搜索展示一定使用给出的标题或描述。

识别两个拟定或已发布页面是否服务相同需求，给合并、区分、支持内链等建议。已有站点不自动改URL、删页或迁移；这些变更先说明影响并由用户决定。

## 六、首次建站报告

按 [报告与关键词台账模板](references/report-template.md) 交付：

1. **一页结论**：市场、语言、产品范围、重点需求、首批页面与当前数据覆盖、关键未确认条件。
2. **有来源的关键词表**：原词、词簇、意图、近似月搜索量及周期、SEO难度等实际取得指标、来源与更新时间、优先级理由。
3. **页面—关键词—位置表**：每页主词／辅助词，Title、H1、正文模块、图片和内链怎么使用；不只建议“首页放核心词”。
4. **逐页制作说明**：页面结构、买家要获得的答案、可用资料和缺项、CTA、内部链接、第一版必做与后续扩展。
5. **内容衔接**：可调整的近期文章与产品页方向，例如四周草案，第一周给具体brief；频率依据用户时间与真实产品，不把示例日程当承诺。
6. **建站交接表**：先做哪页、工具入口或材料位置、教程、可直接用的标题与模块、验收标准。

用户确认重点页和关键取舍后，按授权保存报告及台账；未获保存授权时提供可复制内容。私有业务数据不要写进公开skill。报告完成不自动建站、发文或投广告。

## 七、每周文章与产品关键词报告

每次调用读取上次记录、现有URL、实际已发布／未发布状态、真实新增产品和本周可投入时间。已确认的发布频率继续沿用；未知时给轻量建议让用户选择，不要求必须每周新增SKU。

1. **盘点与去重**：区分已发布、草稿、未执行、已放弃和新增；没有用户确认或访问证据，不能把计划记为已发布。上周未执行项先评估沿用，不每周无条件从头扩词。
2. **定向补数**：复用口径一致且仍适用的数据；对新增产品、重要缺口或需要刷新项调用MCP。说明数据更新时间，月指标未更新不编周环比，也不把单次查询时间当本周需求变化。
3. **本周文章**：给题目、读者问题、主词和辅助词、数据与理由、意图、拟定URL、提纲、应链接的产品页／文章、资料缺口与CTA。优先回答真实买家问题，避免把已有文章换词重复发。
4. **本周产品页**：真实新品给具体关键词、差异、URL、标题、内容与图文要求；没有新品则安排现有产品页补充或优化，说明不必为了词造产品。近似产品不自动分拆大量页面。
5. **旧页优化**：指出承接需求变化、内链缺口、页面重叠或内容不足，并给具体修改；不能只要求“增加关键词次数”。
6. **发布与验证安排**：依据实际产能安排文章、新品／旧页任务和优先级，给每项完成标准和下次复盘指标。内容与页面发布按用户授权执行，本skill默认交付报告。

网站上线后如有用户授权的Search Console等真实数据，可辅助分析展示、点击、CTR和查询／页面关联；它与DataForSEO的市场估算分开。不把工具估算当已获流量，也不因一周无变化就认定失败。

定期报告指每次调用时按周期生成，不表示创建了自动任务。只有用户明确要求定时运行时，才使用环境支持的自动化机制设置，并另行确认访问条件和范围。

## 八、教程、卡点与持续记录

需要用户操作数据工具时给具体官方入口、相关教程与中文步骤；MCP参数与报错通过当前工具schema和官方资料排查。只补必要条件，不把研究任务交回用户。

问题处理保留当前阶段、已查词、任务ID、时间与市场参数、已成功结果和待办。先查明错误，再修复并从断点继续；未知请求状态不立即重复付费提交。用户的补充默认是当前任务的修正，不重启问卷。

最后给简洁行动表：本次先做什么页面或内容、依据、用什么词与材料、完成标志、下次带回什么结果。没有数据时如实交付暂定版和缺项；不声称已经验证流量或能保证排名与成交。
