# Day3：备齐资料、账号与素材，接着就能建站和运营

Day1选方向，Day2定销售与实施方案，Day3把开始搭建独立站和运营社媒所需的准备收齐。沿用已选产品与路线，不重新选品，不再只交一份计划；实际核实供应、准备可用资料与素材、落实基础账号和适用收款申请。

并行推进：**产品认知与供应核实**、**图文与客户问答素材**、**业务身份／邮箱／社媒账号／建站账号及适用收款准备**。Day3收口后，下一阶段直接进入独立站页面搭建、社媒主页装修、首批内容发布与持续运营。此处不把实际网站搭建上线或持续发帖列为Day3完成条件；用户明确要求提前实操时按授权执行并标为提前完成，不强迫回头补已完成步骤。

Day是阶段而不是一个日历日。准备限定为当前首版建站和首轮运营真正需要的内容，不无限调研、扩展产品或囤积素材。供应商等待、样品验证、审核等外部事项保留待办，不伪造结果；分别说明它们是否阻断建站、发内容或后续收款接单。

用户要求创建或修改本skill时只完成文件工作，不开始业务访谈、付费生图或供应商联系。

## 启动与分工

1. 从当前对话、用户提供的Day1报告与Day2实施表、获准读取的私有记录中提取产品、规格、客户与市场、预算与时间、已选渠道、站点方案、资金边界及未核实项。不要遍历无关私有文件。
2. 已有信息直接沿用，缺材料只补影响当前任务的缺口，不重做整份访谈。产品未确认时先补方向选择；不知道规格时先研究并解释，不让用户凭空回答专业问题。
3. 给出当前最值得推进的动作、可并行项和预期产出。每轮仅在必要时询问1–3个个人条件或关键取舍；弹窗可用则用弹窗，不可用用文字继续。
4. AI承担研究、比较、材料准备与已授权执行；用户提供实际事实，决定供货取舍、样品投入、价格与对外承诺。没有经验、会建站、不垫付等条件均不能预填。

公开研究和草稿整理主动推进。联系、发消息、付费生成、拿样、注册、付款及公开发布按已有授权执行；需要补授权时先准备好具体对象、内容、范围与成本。查到联系方式或发现已登录账号不等于获得发送授权。

在执行下述工作时，默认使用 [逐步操作与教程规则](references/step-by-step-guide.md)。先给简短路线和当前第一步，不一次倾倒全部教程。每项动作都要说明“教程在哪”，让不会操作的使用者能找到入口并照做；用户已熟悉的步骤可简化。

## 默认交互：当前一步讲清，遇到不会有教程

- 每步写清目标、实际操作入口、直接教程链接、所需材料、中文操作步骤、预期结果和验收方法。教程不是一句“参考官网”，而是能找到本步说明的具体页面，附标题、语言和适用产品或地区。
- 当前入口与教程先查证，优先官方帮助或产品文档。入口不等于教程，两者分列；搜索结果页不能当作已核实教程。无直接官方教程时，结合已核实资料整理本步中文教程并附依据；第三方视频或图文仅作明确标注的补充，不编造链接或声称已经验证。
- AI能在已有授权下做的研究、整理和操作主动完成，不把所有任务改成用户手工操作，也不要求每点一次按钮都确认。必须本人操作、缺关键输入、需实际授权或需要用户验证结果时，才交付当前步骤并等实际结果。
- 用户说“不会”“找不到”“页面不一样”时，停在该卡点，解释术语、定位当前页面和重写小步骤，必要时请其提供不含敏感内容的页面描述或截图。不能只重发链接、要求用户自己看完或直接跳到下一项。
- 未取得执行证据或用户实际反馈，不标已完成；已经完成的步骤不重做。遇到等待供应回复或账号审批，记录待办并推进不依赖它的工作。用户要求完整教程时可一次提供，仍保留依赖与完成标准。

## 问题处理与流程连续性

用户在执行中提出的问题默认是当前流程的卡点或补充，而不是取消原任务。保留当前步骤、已经完成的事项、已选方案、授权范围和下一步；先解决问题，再接回原流程。只有用户明确改目标或要求停止时才替换或终止。

按 [逐步操作与教程规则](references/step-by-step-guide.md) 的排障闭环处理：定位实际问题 → 主动搜索并阅读对应资料 → 解释原因与证据 → 给可执行解决步骤 → 验证结果 → 更新记录并续接。不能只给搜索词或链接，把判断交回用户；也不能用旧教程机械回答不同的实际问题。

先用已有资料定位；涉及当前界面、报错、规则、费用或不确定事实时主动联网查证，不再问“要不要我查”。只有缺少会改变解决方案的私有信息时，补问1–3项最必要信息。搜索前移除个人身份、账号、验证码和密钥等私密内容，不把用户完整敏感截图或日志发往外部搜索。

有工具和授权可直接验证时继续完成；需要本人操作时给当前解决步骤并等待实际反馈。用户报告成功后，记录其依据，主动给下一步，不要求再次说“继续”；没有证据时不宣布修复成功。持续出错则结合新证据换调查或处理路径，不无意义重试发送、支付、注册或配置写入。

等待用户、供应回复或审核时，留下当前状态、等待事项、恢复条件和下一步，能独立推进的任务继续做。不能联网或需要官方支持时说明限制、准备具体支持问题与可并行工作，不假装解决，也不丢失原任务。新会话仅凭可访问记录恢复，不声称自动记忆。

## 一、产品研究：达到能交流的程度

先复用Day1已有证据，再围绕销售和质量问题补充研究，避免重新写泛泛行业报告。

| 必须研究的方面 | 要回答的问题 |
|---|---|
| 用途与场景 | 谁使用、谁采购、解决什么问题，哪些用途不适合 |
| 规格与选型 | 材料、尺寸、结构、工艺、型号差别，哪些参数影响实际使用 |
| 优点与缺点 | 与具体替代品相比好在哪里，有何代价、限制和不适用条件 |
| 使用痛点 | 使用、维护、寿命或体验中出现什么实际问题 |
| 企业采购痛点 | 起订、定制、质量一致性、包装、补货、交付或采购协调的问题 |
| 竞品与替代 | 常见方案怎么取舍，比较时规格和条件是否一致 |
| 质量与检查 | 容易出什么问题，如何检查，哪些需要样品或专业检测 |
| 客户问答 | 客户会问什么，哪些可回答，哪些必须向供应商确认 |

主动查原始产品资料、说明书、标准适用信息、实际产品页及可访问评价。中文供应信息与目标市场资料结合，不只生成“十大痛点”。时间敏感或高风险信息按当前要求查证。

每项关键结论保留来源、型号或样本、适用范围、资料日期及查询日期。品牌或供应商自述、评价线索、AI推断与实际验证分别标注；少量负评不能推断为普遍需求，缺少负评也不证明没有缺陷。无法访问评价就说明样本限制，不伪造原话或使用经验。

优点必须对应场景与比较对象，缺点不能回避；未知参数不能填“行业常见值”。发现限制影响Day2方案时明确指出，给出调整建议，由用户决定是否改变规格、市场或方向，不擅自换产品。

## 二、把未知项变成供应问题

从产品研究生成询价单，不只问“多少钱”。结合当前产品选取相关问题：

- 确切型号、规格、材料和工艺，各项差异及适用限制。
- 数量档、起订量、定制起订、样品条件、包装、交期、付款与运费承担。
- 常见质量问题、出货检查方式、问题处理原则及可提供的证明资料。
- 索取规格书、真实照片或视频、使用说明；需要检测或认证时核对产品型号、范围与文件有效性，不能只看证书图片下结论。
- 图片和文案是否允许用于独立站、社媒或编辑加工，有哪些品牌与授权限制。

问题按决定是否可做的关键条件优先，其余按需跟进，不把全部研究清单一次复制给每家供应商。

## 三、找匹配货源并实际询价

优先已有有效供应联系和资料；没有时研究1688等适用来源，先核对产品匹配再联系。不单凭低价、销量、店铺标签判断质量或工厂身份，身份与能力保留证据或待核实状态。

先准备可比较的规格、数量、收货条件与询问内容，并按已有授权开展适量询盘。平台商品页价是公开参考，实际回复才记为对方报价；币种、单位、数量、包装、日期与费用承担不同则保留差异，不强行比单价。

有可用的 `b2b-inquiry-mcp` 时，读取其指导与所需README，按其角色、窗口和发送规则执行。本阶段通常是1688买方，但必须按该skill确认本次角色、目标与范围，不能自动使用卖方或国际站账户。`bitbrowser-jev-mcp`是可选浏览器执行层，不是本集业务目标；没有这些工具仍可交付具体询价内容和手动操作步骤，不要求先开发自动化才能做业务。

未知发送状态先查验，不重复发；登录、验证码、权限或预算问题按工具规定停止。取得回复后记录原文依据和时间，区分“草稿”“已发送”“待回复”“收到回复”“已核实”。不下单、不付款，除非另有明确授权。

## 四、用回复核实，而不是照单全信

把研究结论与供应回复逐项对照。对方口头说法、文件证据、样品观察和检测结果分别保存，不能用供应商回复替代独立质量验证。

真实报价与条件到达后，更新Day2测算、起订量和交期假设，指出受影响的展示内容与客户承诺；售价、样品和资金取舍由用户确认。没有回复时继续独立研究、文案结构和账户资料准备，价格与承诺保留待确认。

交付一份简明的“可直接说／有条件说明／必须继续确认”清单。客户问到未知项时，准备如实的确认回复，不编造答案。

## 五、产品图与产品资料

图片依据是当前型号的可靠资料与有权使用的参考图。实际生图前选择已可用的产品图skill、生图MCP或图片工具，核对输入能力、输出要求与用户授权；缺少专用skill时先交付图片需求和提示词，不宣称已经生成。

- 按用途准备适量图片：产品展示、细节或尺寸、使用场景、必要的选型对比。数量由当前页面和渠道需要决定，不为演示工具批量生成。
- 不随意改变形状、结构、材质、连接件、标识、尺寸比例和配件。未验证的性能、认证与功能不能画成事实；数值、英文和单位逐项核对。
- 生成的效果图、场景合成与真实拍摄分开标识，不能当成实拍或样品验证。尺寸和结构关键、无法保持准确时，改用获授权真实照片或准确资料排版，暂停不可靠的生成方式。
- 缺乏可靠参考或图片授权时，列缺项并准备版式；可以生成明确标注的概念示意，不能冒充具体可供货商品。
- 检查最终图的产品一致性、文字与使用范围，再交付适用尺寸、文件和标注方法。密钥只走环境或私密配置，不写入skill、文章、提示词、截图和公开仓库。

## 六、把知识变成客户能看的内容

使用技能包内的 [产品销售手册与实践记录](references/product-sales-handbook.md)，整理产品介绍、参数与选型、优缺点、痛点证据、竞品取舍、质量检查和客户FAQ。先做当前问题需要的内容，不为填满模板补造事实。

FAQ至少覆盖当前产品的核心询问：适用与限制、规格或材质、选型、定制、样品、起订量、价格条件、交期、质量处理等适用项。每题给大白话解释、可用于客户的回复、依据、成立条件及未知项；按目标语言准备，用户需要时附中文对照。客户痛点必须关联可证实的产品能力，不能把痛点直接写成无依据卖点。

把已核实内容整理成可直接用于独立站首版的页面文案、询盘字段、FAQ，以及已选社媒的简介、主页装修素材与首批内容草稿。交付具体文件或可复制内容，不只是“以后需要写文案”的清单。收款沿用Day2已确认方案，企业PayPal按下节落实适用核实与申请；不适用时给依据和替代，由用户决定。

网站和账户工作按实施表并行，不等所有供应商都回复；未核实的价格、认证、身份或交期不能发布。需要用户本人实名、验证码、开户或付款的步骤给具体指引，不代填身份，不宣称已完成。样品、收款申请与建站结果均按实际状态记录。

## 七、账号与建站／社媒素材：开工前备齐

邮箱、已选社媒与必要建站账号的开通或核实属于Day3实际准备，不仅是“建议注册”。页面搭建、主页装修与运营发布属于下一阶段；Day3先把这些操作要用的账号、资料、文案和素材备好。复用已有内容，按授权协助注册，本人验证由用户完成。

按 [账号、收款与开工准备记录](references/account-setup.md) 为每个选定平台填写官方入口、适用地区与账户类型、材料、操作步骤、注意事项、费用和验收方式。步骤依据当前官方说明及实际可见界面，不凭记忆编菜单或承诺一定通过。需要当前平台规定时联网核实；不可联网标未核实并先准备可独立完成的资料。

- **统一业务资料**：准备真实的业务名称、品牌显示名、产品介绍、目标语言简介、业务联系方式、头像及横幅、网站链接。品牌名不能冒充已登记公司，地址和主体信息由用户确认；准备可复制字段，避免让用户重复写。
- **业务邮箱**：复用已有可用邮箱；没有时按预算与域名方案选择。说明邮箱注册、收发测试和账户恢复设置；企业域名邮箱可行时按官方要求配置必要DNS记录并核验。域名购买与付费服务按已有授权，不能假定已有域名或邮箱。
- **社媒账号就绪**：沿用Day2已选平台，按授权完成必要注册与账户核验，提供对应账号类型、官方入口、填写与本人验证步骤。已有账号核实可用性，不重复注册。头像、封面、简介、业务联系方式及首批内容备成素材包；完整主页装修和内容发布放到后续实操，不以未来网站尚未上线为由填写虚构链接。
- **账号基础设置**：按平台可用方式完成安全验证、恢复方式和本人持有的账户归属；不索取聊天中的密码或验证码，不购买账号或提供绕过地区、实名认证和风控的方法。明确哪些按钮由Agent协助、哪些必须本人处理。
- **独立站开工包**：落实已选平台及必要账户访问、预算与域名方案，备好页面结构、产品图、目标语言文案、FAQ、联系方式、询盘字段与接收方案。按实际授权推进域名或账户准备；尚未购买则明确后续购买入口、费用和条件，不假定已持有。交付后续第一项建站动作、教程及上线验收清单。Day3不要求实际搭页面、绑定DNS或上线，后续实操再验证移动端、HTTPS及真实询盘。
- **社媒开工包**：按已选平台备好头像封面、可复制简介、第一批帖子文案及配图、产品知识素材与简单发布安排。数量以首轮需要为准，先有可直接用的一批，不为准备而做完整月度运营。未发布标草稿，承诺与身份不能虚构。

## 八、企业PayPal及收款申请：核实后推进

企业PayPal是本次实施包必须覆盖的具体账户选项，不是只写“准备收款”。先读取Day2决定与用户所在地、经营主体、产品、收款市场和现有账户等真实条件，查当前官方适用性、账户类型、开户材料与使用要求。

- 适用且已选择时，给准确官方注册入口、账户类型、逐步填写说明、主体和身份材料清单、账户与相关银行信息的匹配要求、验证和后续启用步骤，并在授权范围协助操作。本人认证、银行验证和提交确认等按实际要求由本人完成；不代填身份或编造公司、注册国家。
- 按官方来源解释当前适用的收款、跨境、换汇和提现等费用，资金可用或保留条件、争议及退款处理要求。不能把费用未知当免费，不能承诺注册必过或付款立即可用。
- 以实际账户说明如何向客户提供适合当前业务的付款方式，以及是否要与独立站集成；B2B询盘站可先将销售联系与收款流程分开，不强制开发购物车或先接支付接口。未核实收款条件前不收真实客户款，不能为了验收自动扣款、退款或绑定新的付费服务。
- 不适用、材料不足或用户已选其他工具时说明原因与来源。保留PayPal状态，给少量实际适用替代方案及具体办理步骤，由用户选择，不能让用户去虚构条件迁就工具。
- 状态分别记录“材料待齐／可申请／已提交／审核中／已验证／可收款／提现能力待确认”等实际情况。账号创建不等于审核完成、可收款或可提现；无法进入账户确认的能力不能标完成。

## 交付与续接

先给一页结果摘要：今天弄懂什么、实际做了什么、关键新发现、哪些尚待回复或验证、哪些决定需要用户作出。阶段交付包括：

1. 带来源和未知项的产品销售手册、客户FAQ。
2. 针对性的供应询价单、联系记录及真实回复比较；未获发送授权则交付待发送草稿，不能记成已联系。
3. 可用于首版网站和首批社媒的产品图、页面文案、简介、头像封面、FAQ和内容草稿。缺项明确指出，素材准备不能仅以提示词或未来待写清单替代；可靠参考不足时标阻塞并处理。
4. 受新证据影响的Day2方案调整和下一步。
5. 邮箱、已选社媒与必要建站账号的真实准备结果，域名与平台方案、具体教程、建站及社媒开工包和后续验收清单。实际网站搭建、主页装修及运营不作为本阶段必须完成项。
6. 企业PayPal或已确认替代方案的适用核实、申请教程、材料与注意事项，以及申请和验证实际状态。

**最后必须给一张直接开干表**：顺序／前提、做什么、操作入口、教程在哪、怎么做／现成材料、完成标志。通常6–10项，每行的“教程在哪”指向经查证的具体外部教程或本次已交付的详细中文教程位置，不能空填“自行搜索”；标出可并行、等回复和待用户授权项。表后明确先做哪项、完成后带回什么结果。

最终表分清“Day3已完成的准备／剩余前置缺口”与“下一阶段直接开工”。开工行明确独立站首个页面、社媒主页装修与首批发布的入口、教程及现成素材。已完成项给依据，未申请、未批准、未上线分别记录；不适用给理由与替代，不机械重复注册。

## Day3收口标准：下一阶段不必重新准备

按 [开工前交接检查](references/launch-readiness.md) 核对实际成果：产品知识够当前介绍与问答、首版展示事实可靠、供应关键条件及未知明确、图文与品牌素材可用、必要账号和邮箱可访问、建站路线及首项操作明确、社媒装修与首批内容可直接取用、收款申请及其限制有真实记录。满足“能开始建站与首轮社媒工作”即可收口，不等所有未知都消失，不继续扩充大报告。

分别给出“建站能否开始”“社媒装修／首批发布能否开始”“真实收款接单能否开始”及依据。外部审核或样品等非阻断项进入待办；会影响首版真实性、工具访问或必要素材的缺口先解决，不能把所有内容都标准备完成。

有未验证项不代表毫无产出，但不能把草稿、示意图或待回复写成业务已验证。按用户授权把真实进展保存到私有位置，检查上传范围；没有文件工具就给可复制记录，不声称已保存。

用户要求视频或文章时，按真实成果整理；不让拍摄需要改变业务顺序，不把工具演示当业务结果。后续使用可用的持续实践指导处理回复、样品、客户反馈及问题；本skill只创建时不启动这些操作。
