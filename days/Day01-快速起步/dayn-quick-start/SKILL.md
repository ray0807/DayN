# Day1：个人条件分析与商品方向研究

至少10个不同的具体产品是中间候选池。最终交付是经过多轮筛选、由用户确认的一个优先产品及其详细外贸深度调研报告。确认产品是中间决策节点，不能在此宣布Day1完成。AI负责思考、调研和综合分析，用户提供个人事实并做关键选择。准备阶段共两天：Day1定卖什么，Day2定怎么卖；外部验证在实践中进行。Day指一个阶段而非一个日历日，访谈和研究需要更久时按实际进度完成，不为赶在一天内而压缩候选、收敛轮次或报告内容；与Day2有重复的分析照常保留。

## 范围与阶段边界

围绕B2B实物商品外贸。技术、AI或自动化是辅助能力，不能因用户会技术就推荐AI服务、软件外包或SaaS出海。只有用户明确改变业务目标时才调整范围。

Day1可以查产业带、公开供货特点、典型起订与样品条件，用于判断产品可得性、成本和实施难度；不以供应商名单、联系方式或联系教程代替产品研究报告。不开展供应商联系，不起草供应合作申请，不要求先取得佣金合作答复才完成选品。供应商筛选、联系、打样和合作谈判属于后续阶段。

按用户要求只执行当前阶段。报告交付后帮助理解、修正比较并选择深入方向，形成后续待办；不自动进入Day2，不把连续对话解释成无限提问。用户要求改技能时只修改并校验文件，不启动访谈或业务研究。

## 通用用户条件与默认交互

每个人的条件单独确认。只能使用当前使用者本人明确回答，或其确认有效且属于本人的记录；技能、README、例子、原作者或其他会话的条件不能预填。每条已确认事实注明回答依据。未知不填零，“没有供应资源”也不意味着没有其他经验。“想用AI”不能推断会开发或自动化。

默认使用当前模式允许的交互弹窗工具；有request_user_input_async时优先使用。事实用自由文本，适合分类时用少量选项并允许补充，不推荐或预选用户的个人事实。每次1–3个问题，避免在正文重复问一遍。工具不可用或用户要求文字时才退回聊天提问。

收到回答后合并事实，简短解释它如何改变方案，再判断补问还是研究。需要补问时在同一轮实际发出弹窗，不能只说“接下来问”就结束；条件足够就实际研究，不问“是否继续调研”。待回答、已知事实、证据、建议、决定和未知项沿用同一条上下文链。

异步弹窗受理、预选项或等待超时都不是答案。等待必要输入可以结束当前响应，但不宣布流程完成、不催用户发“继续”；收到回答直接续接。不同会话只使用可访问的记录，不声称自动记忆。

## 访谈：收集会改变选品的信息

按已有信息选最重要的缺口，不把下表变成一次性必填问卷。新手不需要先回答专业分析题，有经验者围绕实际产品和市场深入。

| 信息 | 了解什么 | 用于什么判断 |
|---|---|---|
| 经历与起点 | 所在地区、工作经历、外贸和产品经验 | 学习负担、可利用的经验与接触条件 |
| 投入 | 全职或兼职、可持续时间、业务预算、探索期限 | 工作量、资金要求及试错方式 |
| 资源与开展条件 | 本人实际能使用的供应或客户资源、经营主体状态 | 是否有可核实优势、后续哪些条件需落实 |
| 沟通 | 阅读、邮件、口语与电话能力，常用工具 | 客户沟通场景与支持需求 |
| 竞争偏好 | 对价格竞争、定制、专业选型和服务协调的态度 | 差异化方向及其实际负担 |
| 学习与执行 | 愿意学习到什么程度，能承担哪些工作 | 是否适合复杂产品、需求协调或长销售周期 |
| 样品与费用 | 是否接受打样、谁付款、是否接受垫付 | 各产品的样品与现金要求是否匹配 |
| 兴趣与限制 | 感兴趣、明确不愿做的商品、用途或市场 | 候选范围，不要求用户凭空选行业 |
| 经营方式与客户类型 | 单人或团队，倾向小单快返还是走量，想服务大客户、小型企业还是经销商 | 候选是否匹配可承接的订单形态与客户开发难度 |

例如先了解地区、经历、供应起点与时间，再补预算、语言、竞争偏好和样品边界。兴趣与不愿做的品类、经营方式与客户类型会直接改变候选范围，必须在首次产出候选前问到，不能等用户否定候选后才补问。

用户提到的已有资源（熟人工厂、货源、客户）只作为候选来源之一，不能主导初始候选范围；初始候选池须覆盖资源之外的多个类目，再说明资源对各候选的实际帮助。缺专业知识由AI解释并调查，个人偏好不明确则用实际工作场景帮助理解。用户没有产品兴趣时，按机会和适配性研究，不能一直逼其选行业。

投入、经历、竞争偏好及重要执行限制足以影响筛选时即可开始研究，独立任务边研究边补问。会影响最终推荐的个人事实仍未知时保留条件性判断，不代填。零业务预算属于约束，不意味着能无成本独立完成交易；指出需在后续验证的付款或合作前提，不据此先跳入供应谈判。

## 调研：扩大范围，再形成候选

先把个人条件转成筛选标准，解释哪些偏好带来什么取舍。标准产品不必然只能卷价格，定制也不必然高利润；分别检查差异化价值与竞争证据。

研究多个类目，再筛出至少10个可区分的具体产品候选。不能以同一产品的尺寸、颜色、款式凑数量，不能过早根据偶然线索锁定单一方向。用户限定行业时尊重其范围，研究不同用途或工艺的实质产品；范围不足10个时解释限制并询问是否扩大，不造产品。

每个候选调查：
- 具体商品及采购用途，企业买家类型和初步目标市场。
- 真实海外产品、渠道或买家案例；为什么购买或考虑更换供应来源。公开存在不等于正在采购。
- 竞争与替代：当地供货、同类供应、价格透明度，跨境采购能提供什么价值。
- 差异化路径：定制、规格匹配、质量一致性、交付或采购协调等；需要什么能力，用户能否建立，而非泛称“服务好”。
- 学习、技术、质量、售后和合规负担；物流特点、典型起订与样品要求。
- 业务预算、打样及垫付边界如何影响可行性；条件未验证时标出前提。

主动使用国内外搜索、页面读取、贸易及市场资料，优先官方、原始数据、真实企业与产品资料。市场、政策、费用、物流和准入的当前事实必须查证。关键判断交叉核查，保留来源冲突与局限。

同一来源或不同来源的数字前后矛盾时，如实标明矛盾，不择一引用。

每个候选至少有直接支持其用途或渠道的来源；重点推荐候选另查竞争、执行难度及关键准入信息。来源记录直接链接、资料日期（未标则说明）、查询日期、地区与产品范围。企业自述尚未独立核实要注明。贸易统计不等于订单，网页价格不等于实际成交价，不能编造需求、利润、认证或效率数字。

资料不足仍可列为“待验证候选”，不计为已确认机会；不为凑10项夸大推荐。无法联网时说明报告未达到证据要求，完成结构和独立分析，不假装已调研或将研究交回用户。不声称搜尽全网。

## 中间交付：至少10个具体产品候选

初始研究完成后，向用户展示个人条件分析及至少10个实质不同的产品候选。统一比较类目与产品、目标买家、采购用途、初步市场、需求或渠道证据、差异化、竞争、学习与合规负担、样品和资金要求、个人适配及来源。

这是共同筛选的起点，不是最终交付。可指出3–5个值得重点比较的方向，但不能交付一个推荐清单就宣布Day1完成，也不能要求用户凭空从10个中直接挑唯一答案。候选可分段连续展示，不每段索取“继续”。

每个候选给出关键利弊和证据。至少10项是覆盖要求，不代表都值得做；证据不足标待验证，受用户限定范围影响数量不足时说明并询问是否扩大。不造评分、利润或成交概率。

## 多轮收敛：与使用者一起筛到一个产品

这里的询问对象是使用本技能的用户。Day1不擅自联系海外客户或供应商；未来买家反馈属于后续实际验证。

1. 根据候选之间真正影响适配性的区别选择当前决策点，例如客户沟通负担、学习深度、定制复杂度、销售周期、样品和资金条件。先解释实际工作与取舍，再用弹窗询问用户接受程度或偏好，每轮1–3个问题。
2. 用户回答后，将新条件用于比较现有候选，说明哪些保留、哪些降低优先级或排除，以及具体理由。不只重复其答案，不随意删产品，不把用户未了解的专业判断交给用户。
3. 对能改变候选排序的外部信息主动补充调研。个人取舍由用户回答，市场、竞争、成本和产品事实由AI查证。继续独立研究，不把每轮变成选品投票。
4. 展示本轮剩余候选和变化，再发出下一项真正必要的问题或开展补充研究。可采用10余项→4–6项→2–3项→1项的节奏，但不强制轮数或数量，按证据与回答收敛。
5. 用户不同意排除理由时解释、复核并调整；发现原候选都不适合时先询问不满意的原因，再重新研究候选，不为了剩一个而硬选。重新研究同样需要至少10个有直接来源支持的候选，标为待验证的项目不计入数量。新条件推翻判断时允许恢复候选。
6. 最后两三个产品做直接比较，AI给明确推荐、代价和成立条件。以弹窗请用户确认优先开展哪个产品，或指出仍需解决的顾虑。用户已明确选定可跳过重复确认。

持续推进不代表越过未知条件或代替用户选择。等待必要回答保持待定状态；收到回答直接衔接，不要求“继续”。若无法支持唯一推荐，明确缺口并补研究，不用虚假的确定性结束流程。

## 最终交付：一个明确的优先产品

用户确认一个优先产品后，先整理选择结果，再立即进入下述深度调研，无需用户另发“继续”或重新许可公开研究。选品结果包含：
- 具体类目、产品定义和用途，避免仅剩宽泛行业名称。
- 目标企业买家类型与初步市场，以及为何适配。
- 当前使用者选择理由、可建立的差异化及主要学习负担。
- 关键来源、筛选过程及重要排除理由。
- 尚待验证的需求、成本、质量、合规及合作前提。
- 后续阶段的验证待办，不交付供应商联系方式或合作申请。

“一项优先产品”表示下一阶段集中验证的起点，不等于市场已验证、保证盈利或永远不能调整。未得到用户确认时只交付阶段结果并继续筛选，不宣布完成。

## 唯一产品确认后：详细外贸深度调研

确认一个优先产品后，主动完成国内外资料研究和综合分析，交付足以指导下一阶段验证的详细报告，而非几段行业介绍或链接清单。根据产品性质决定深度与篇幅，重点章节展开分析，不为长而堆砌。

### 研究与分析要求

1. **产品定义与业务边界**：用途、细分品种、材料、规格、工艺、关键质量指标、替代品、采购计量单位。区分不同用途或风险等级，说明当前具体研究哪一款或细分范围。
2. **全球需求与贸易格局**：适用商品分类和可能的HS编码、主要进口市场、可获得的近年贸易规模及趋势、来源国、需求驱动和季节性。核查数据年份、口径、单位和覆盖；HS统计范围不等于具体产品市场，不能用大类总额冒充细分规模。分类不确定时说明候选和核实依据，不擅自作最终报关归类。
3. **目标市场比较**：比较多个有依据的国家或地区，综合需求、竞争、本地供货、物流、准入、沟通、付款和用户条件，推荐首选及备选市场。不能只按进口规模排序。既定市场已有授权时以它为主并说明比较边界。
4. **企业买家与采购过程**：具体买家类型、用途、决策角色、采购触发因素、关注指标、供应商准入、常见采购与复购过程。附真实企业和公开页面作为研究案例，说明哪些只是潜在匹配，不冒称当前采购或已有联系。
5. **竞争与差异化**：当地及跨境竞品、替代方案、可核实的价格区间与条款差异、优势和短板、可能的客户不满。区分事实和假设；提出用户可逐步建立的实际价值，不仅写“高品质低价格”或“做好服务”。
6. **供应与生产特征**：产业分布、典型工艺、质量控制、可查的起订、交期、定制和样品条件。仅用于产品可行性判断，不转成找供应商、联系方式或合作申请，不实际联系企业。网页供货条件需要后续实际验证。
7. **成本、报价和资金**：梳理产品、包装、打样、国内运输、出口服务、国际运输、保险及目的地费用。用明确标注的情景测算展示数量、货值、运费等变量，区分实际公开报价与假设；说明币种、日期、贸易条款和不含项，不编造利润率。决定可行性的关键变量（如出厂价、国际运费）须查找公开参考价并注明来源；确实查不到时说明缺口，目标值与推算值要和查证值分开标注。出厂价优先查1688、义乌购（chinagoods）、工厂官网等公开货源页，记录单价、起批量、定制起订量、打样费和对应数量档；1688搜索页常拦截自动访问，可改查搜索引擎收录的商品页、工厂页和行情页，仍不可得时给用户一份几分钟可完成的手动查价清单。查看公开页面不算联系供应商。货源起订量与计划给客户的起订量不一致时须指出并给出可行的处理方式。结合用户预算、垫付和样品边界分析成立前提。
8. **物流与交付**：体积重量、包装、运输方式、可能的损坏、交付周期与贸易条款下责任。没有可靠现价或实际测量时提供计算方法和待核实项，不造实时运价。
9. **合规与风险**：针对产品和目标市场核查出口限制、进口要求、标准、检测、标签、知识产权及适用环保等事项，区分强制要求、客户要求与自愿认证。使用当地官方法规和主管机构来源，说明适用条件和资料日期；不把同一认证套给所有产品。法律、税费和HS判断有未决问题时列出核实对象与依据。
10. **市场进入与客户开发策略**：结合用户的实际语言、经验、时间和预算，推荐定位、客户筛选信号、可调查渠道、资料需要、需求确认问题和可能的销售周期。指出现有能力不足与可行补足方式，不开展实际发送、发布或客户联系。
11. **风险与后续验证计划**：商业、付款、质量、交付、合规和合作前提；重要假设、能推翻判断的证据、下一阶段验证顺序与停止或调整条件。不得承诺成交、无成本完成交易或固定期限盈利。

不适用的章节明确解释不适用。数据不可得时写缺口、可用替代证据及局限，继续分析，不能空造数字或把整份研究交给用户。补问只用于会改变判断的个人信息或价值取舍，公开专业问题自行查证。

### 来源与报告交付

关键数据与结论就近附直接来源链接。记录资料发布日期或更新日期、查询日期、地区、范围及口径；未标日期如实说明。重点结论交叉验证，对冲突解释或保留分歧。优先官方贸易数据、法规和原始企业资料；企业宣传、商业估算与AI推断分别标明。

最终报告包含：结论与成立条件、产品范围、上述各项详细分析、市场比较及成本情景表、风险和后续验证待办、来源目录。先回答“这个产品对当前用户是否值得继续、从哪个市场和买家切入、需要哪些前提”，再展开证据。资料篇幅大时连续分段完成，不在每段索取“继续”。

报告默认完整交付在聊天中，用户要求保存时才写入授权位置。深度研究若发现重大障碍，先解释证据并更新建议；需要换产品时弹窗让用户判断，再对最终确认产品做深度调研，不隐瞒不利证据以维持原选择。

## 收尾、续接与记录

Day1完成标准：至少10个初始候选经多轮分析筛到用户确认的一个优先产品，并完成该产品的详细外贸深度调研报告。未选定继续收敛；已选定但报告未完成时继续研究，不提前结束。

报告交付后，用弹窗询问用户是否保存一份Day1决策记录，供Day2在新对话中读取；默认建议保存到项目中不会上传的 `records/` 目录，也可由用户指定其他私有位置。记录按 [决策记录模板](../../../docs/decision-record-template.md) 整理，至少包含：已确认的个人条件及依据、选定产品与目标市场和买家、关键数据及来源、成本测算与假设、主要备选产品、待验证项。用户不保存时提醒：新对话无法读取本次聊天，进入Day2时需要把报告或记录提供给Agent。

用户追问或修改条件时沿用链条，补研究并更新推荐；不重启问卷。选择后整理选择理由、关键未知和后续验证待办。只有用户要求进入后续阶段时再开展供应商开发等任务。

研究报告默认在聊天交付，用户要求保存时再写入授权位置；私人预算、客户及供应资料不写进公开技能。录制脚本只在聊天提供，不保存到项目或上传GitHub。实际发送、支出、发布和承诺遵守已有授权，本技能不授予额外权限。
